## 1. 방향

1. **AI 토큰 0 기조 유지** — 원래 Phase 3(Claude로 운세 문장 생성)는 타로에서 검증한 방식(규칙 기반 이야기 + 외부 AI 이어 보기)으로 대체한다. Claude API 연동은 트래픽·수익 구조가 생긴 뒤 다시 판단한다.
2. **재방문 장치를 로그인 없이 먼저** — TIL 캘린더·스트릭은 로컬 저장으로 시작하고, 로그인·DB는 필요가 확인되면 붙인다.
3. **새 기능 전에 품질 기반** — 배포가 자동으로 되는 만큼 CI·브라우저 확인·SEO 기본기를 먼저 깐다.

## 3. P1 — 타로 경험 다듬기 (약 1–2주)

### 3.1 결과 공유 링크 + 공유 이미지 (가장 효과 큰 과제)
- 지금 결과는 기기에만 저장돼 공유할 수 없다. 결과는 `seed + picks + spread + topic`으로 **서버에서 그대로 재현**되므로 DB 없이 주소만으로 공유할 수 있다.
- `/tarot/r?t=love&s=reunion&seed=…&p=3,17,29,44,61&rev=1` → 서버에서 해석해 결과 화면(카드는 모두 펼친 상태) 렌더.
- 질문은 개인적인 내용일 수 있어 **공유 주소에 넣지 않는다**. 공유할 때 "질문 포함" 체크 시에만 넣는다.
- `opengraph-image.tsx`(ImageResponse)로 뽑은 카드 이미지 + 결론 한 줄을 그린 공유 카드 생성.
- 결과 화면에 "링크 복사" 버튼, 휴대폰에서는 기기 공유 시트(`navigator.share`)도 함께. 카카오톡 전용 공유 버튼은 맨 마지막(9장 P5)에.
- 완료 기준: 공유 주소를 새 브라우저에서 열면 같은 결과가 나오고, 메신저 미리보기에 카드 이미지가 보인다.

### 3.2 카드 고르기·연출
- 펼친 카드 키보드 조작(←/→ 이동, Enter 선택) — TAROT_PLAN 7장에 계획했지만 아직 버튼 포커스 이동만 됨.
- 고른 카드가 스프레드 자리로 날아가 놓이는 연출, 휴대폰에서는 부채꼴 대신 두 줄 배치 검토.
- `prefers-reduced-motion`은 현재처럼 유지.

### 3.3 작은 개선
- 같은 주제를 짧은 시간에 반복해서 보면 "같은 질문을 반복하면 흐려져요" 안내 (막지는 않음).
- "역방향 포함" 설정을 기억.
- 카드 사전에 **상징 요소**(그림 속 인물·소품·색의 의미) 섹션 — 78장 데이터 작성이 필요해 메이저 22장부터.
- 최근 기록 전체 보기·삭제 (지금은 최근 5개만 표시).

### 3.4 해석 문장 (TAROT_AI_PLAN 후속)
- **T8-3**: 문장 틀 표현 변형 확장 — 자리마다 2개 → 4~5개 (한 번만 초안 생성 후 검수해 커밋, 운영 중 토큰 0).
- **T8-4**: "Claude에서 이어 보기" 버튼 추가(`claude.ai/new?q=` 동작 확인 후), 버튼 클릭 수 집계(Vercel Analytics 커스텀 이벤트 — 요금제 확인)로 어떤 AI를 많이 쓰는지 확인.

## 5. P2 — 사주 상세 풀이 · 궁합 (약 3–4주)

### 5.1 사주 상세 풀이 `/saju`

**목표:** 온보딩에 저장된 프로필 하나로 "내 사주"를 한 화면에서 깊게 본다. 홈의 운세 카드에 "내 사주 자세히 보기" 링크로 진입.

**데이터 — 패키지에 있는 것과 직접 만들어야 하는 것**

| 항목 | 출처 | 상태 |
| --- | --- | --- |
| 사주팔자 4주 (천간·지지·오행·음양·띠) | `analyzeSaju().pillars` | ✅ 패키지 |
| 오행 분포, 과다·부족 오행 | `fiveElements`, `dominantElements`, `weakElements` | ✅ 패키지 |
| 신강/신약, 용신·희신과 근거 | `dayMaster.strength`, `yongsin`(+`reasoning`) | ✅ 패키지 |
| 주제별 풀이 (종합·연애·재물·직업·건강) | `analyzeSaju(…, { fortuneType })` → `fortune.summary / guidance / caveat` (주제마다 1회 호출) | ✅ 패키지 |
| 십신 (각 주의 천간·지지) | `lib/saju/ganji.ts`의 `tenGodOf` 재사용 (지지는 본기 천간 기준) | 🔧 재사용 |
| 지장간 (지지 속 천간) | 지지 12개 → 여기·중기·정기 정적 표 | 🔧 새로 작성 |
| 원국 합·충 (지지끼리) | `ganji.ts`의 `isHarmony`(육합)·`isClash`(충) 재사용, 삼합·형은 새로 추가 | 🔧 일부 추가 |
| **대운** (10년 단위 8개) | 방향: 연간 음양 × 성별(양남음녀 순행, 음남양녀 역행). **대운수: 출생 시각 → 다음(순행)/이전(역행) 절기까지 일수 ÷ 3** | 🆕 **절기 시각 데이터 필요** |
| 세운 (올해·내년) | 그해 연간지(2026 丙午) × 일간 → 십신·합충 — 오늘의 운세 로직을 연 단위로 | 🔧 재사용 |
| 12운성 | 정적 표 | 후순위 |

> **대운 선행 과제:** 지금 쓰는 `korean-lunar-calendar`에는 절기 시각이 없다. 후보 ① 절기 계산이 들어 있는 라이브러리(예: `lunar-javascript`) 도입 ② 1900–2100년 절기 시각 표를 한 번 만들어 커밋. 착수 전 라이선스·정확도(공개 만세력과 대운수 20건 대조)로 결정.

**API:** `POST /api/saju` `{ profile }` → `SajuDetail` (서버에서만 계산 — `saju-fortune`은 서버 전용). 같은 프로필이면 결과가 같으므로 응답에 캐시 헤더.

**화면 구성 (위에서 아래로)**

1. **요약 헤더** — 일간 캐릭터 한 줄(예: "기토(己土) — 너른 들판처럼 품이 넓은 사람"), 신강/신약, 용신. 일간 10개의 캐릭터 문장은 새로 작성.
2. **명식 표** — 4열(시·일·월·연) × 행(천간 십신 / 천간 / 지지 / 지지 십신 / 지장간), 오행별 색. 출생시 모름이면 시주 칸은 "?"와 안내.
3. **오행 분포** — 목·화·토·금·수 막대 5개(CSS로 충분, 차트 라이브러리 불필요), 과다·부족 표시.
4. **용신·희신** — 근거 설명 + 생활 팁(행운 색·방향과 연결).
5. **주제 탭** — 종합·연애·재물·직업·건강: 패키지 풀이 + 실천 조언 + 주의 문구.
6. **대운 타임라인** — 가로 스크롤 카드(시작 나이·간지·십신·한 줄), 지금 대운 강조.
7. **올해·내년 운 (세운)** — 십신·합충 기반 한 문단.
8. **한계 안내** — `limitations`, 출생시 모름이면 시주 관련 해석 "잠정".
9. **AI에게 물어보기** — 간지·십신·오행·용신만 담은 프롬프트(생년월일시는 넣지 않음), ChatGPT·Gemini 이어 보기 재사용.

**단계**

| 단계 | 내용 | 예상 |
| --- | --- | --- |
| 5.1-a | API, 요약 헤더·명식 표(천간·지지)·오행·용신·주제 탭 — 패키지 데이터만으로 | 4일 |
| 5.1-b | 십신·지장간·원국 합충, 일간 캐릭터 10개 | 3일 |

### 5.2 궁합 `/compat`

**흐름:** 나(저장된 프로필, 없으면 먼저 입력) → **관계 유형** 선택(연인·썸·친구·동료·가족) → 상대 입력(닉네임 선택 + 생년월일·시간·성별·양/음력 — 온보딩 폼 재사용) → 결과.

**API:** `POST /api/compat` `{ me, partner, relation }` → `checkCompatibility` + 자체 분석.

**분석 항목**

| 항목 | 출처 | 설명 |
| --- | --- | --- |
| 총점 (0–100) | `checkCompatibility().score` | 총점은 패키지 점수를 그대로 쓴다 (기준을 섞지 않음) |
| 공통·보완 오행 | `sharedElements`, `complementaryElements` | "내가 부족한 기운을 상대가 채워 줘요" 도식 |
| 살펴볼 점 | `focusAreas`, `summary` | 패키지 문장 |
| 일간 관계 | 🔧 `tenGodOf`로 서로의 일간 십신 (예: 나에게 상대는 정관) | 관계에서 서로의 역할 해석 |
| 일지(배우자궁) 관계 | 🔧 `isHarmony`·`isClash` + 5.1에서 추가하는 형 판정 | 생활 리듬·가까워질수록의 궁합 |
| 띠 궁합 | 🔧 연지 삼합(5.1에서 추가)·충 | 재미 요소, 비중 낮게 표시 |

**결과 화면:** 총점 + 한 줄 → 두 사람 일간·오행 비교 → 잘 맞는 점 3개 / 조심할 점 3개 → 관계 유형별 팁(연인은 감정 표현, 동료는 협업 방식) → "우리 관계 타로로 보기"(관계 스프레드 바로가기) → AI 이어 보기 → 공유 카드.

**개인정보 원칙**
- 상대 정보는 **기본적으로 저장하지 않음**. "최근 궁합 기록 남기기"를 켰을 때만 기기에 저장.
- 공유 이미지에는 **닉네임·점수·한 줄**만, 생년월일은 넣지 않음.
- 공유 링크는 결과가 아니라 "나도 궁합 보기" 시작 화면으로 (결과를 다시 만들려면 생년월일이 필요하므로).

**단계**

| 단계 | 내용 | 예상 |
| --- | --- | --- |
| 5.2-a | 입력 흐름·API·기본 결과(패키지 데이터) | 3일 |
| 5.2-b | 일간·일지·띠 분석과 관계 유형별 문장 | 3일 |

## 6. P3 — 다시 찾아오게 하기 (1단계 약 1.5주 + 2단계 1–2주)

**핵심 아이디어:** 오늘의 운세와 오늘의 타로는 "프로필 + 날짜"로 **언제든 다시 계산**된다. 그래서 기록에는 결과 전체가 아니라 **방문 사실·메모·적중 여부**만 저장하면 된다 — 로그인 없이도 가볍게 시작할 수 있다.

### 6.1 기록 모델 (기기 저장)

```ts
// localStorage "til:journal:2026-09" — 월별로 나눠 저장
interface JournalDay {
  date: string;                 // "2026-09-25" (KST)
  visitedAt: string;            // 첫 방문 시각
  fortune?: { score: number; headline: string };   // 달력 표시용 요약
  tarot?: { cardId: string; reversed: boolean };   // 오늘의 타로
  readings: string[];           // 그날 본 상세 타로 seed (기존 기록과 연결)
  hit?: "yes" | "half" | "no";  // "오늘 운세 맞았나요?"
  memo?: string;                // 한 줄 회고 (최대 100자)
}
```

- **자동 기록 시점:** 홈에서 오늘의 운세를 불러왔을 때 / 오늘의 타로를 뒤집었을 때 / 상세 타로 결과가 나왔을 때.

### 6.2 TIL 캘린더 `/calendar`

- 월 달력: 날짜 칸에 **운세 점수 색(5단계)** + 그날 오늘의 타로 미니 카드.
- 날짜를 누르면 그날 운세 요약·카드·상세 타로 기록·메모. 방문하지 않은 지난 날짜도 "그날의 운세 다시 보기"(다시 계산). **미래 날짜는 잠금** — 내일 운세는 내일 와서 보도록.
- 월간 요약: 평균 점수, 가장 많이 나온 수트·메이저 카드, 적중률.

### 6.3 "오늘 어땠나요?" 회고 — TIL(Today I Lucky)다운 기능

- 다음 방문 때 어제의 카드와 한 줄 운세를 보여 주며 "맞았나요? 👍 · 반쯤 · 👎 + 한 줄 메모". 저녁 6시 이후에는 오늘 것도 바로 회고 가능.
- 회고가 쌓이면 "내 운세 적중률", "잘 맞는 카드" 같은 개인 통계.

### 6.4 연속 방문·배지

- KST 기준 **오늘의 운세를 확인한 날**을 방문으로 셈. 연속 일수 + 최고 기록.
- 배지: 3 · 7 · 14 · 30 · 100일, 첫 회고, 메이저 22장 모두 만나기(오늘의 타로 기준) 등.
- 홈 헤더에 "🔥 7일째" 표시, 캘린더 상단에 배지 모음.

### 6.5 PWA (홈 화면에 추가)

- `app/manifest.ts`(이름·아이콘·테마색), 아이콘 세트.
- 두 번째 방문부터 "홈 화면에 추가하면 매일 한 번에 열 수 있어요" 안내(닫으면 다시 안 띄움).
- 계산은 서버에서 하므로 오프라인 기능은 두지 않고, 오프라인이면 안내 화면만.

### 6.6 백업

- 설정 화면에서 기록 **JSON 내보내기·가져오기** — 기기를 바꿔도 이어 갈 수 있게. "기기 저장이라 브라우저 데이터를 지우면 사라져요" 안내.

### 6.7 2단계 — 알림·로그인 (필요가 확인되면)

| 과제 | 필요한 것 |
| --- | --- |
| **웹 푸시 알림** "오늘의 카드가 도착했어요 🃏" | 구독 정보 저장소(Vercel 연동 Postgres/KV 등), 매일 오전 8시(KST) Vercel Cron 발송, VAPID 키. iOS는 홈 화면에 추가한 PWA(16.4+)에서만 받을 수 있어 안내 필요 |
| **로그인·동기화** | 카카오/구글 로그인, Postgres(PLAN 5장 모델). 첫 로그인 때 기기 기록 업로드 동의, 생년월일 암호화 저장, 탈퇴 시 즉시 삭제 |

## 10. 결정 사항

**정해진 것 (2026-09-25)**
- 통계 도구: **Vercel Analytics** (P0). GA4는 차후(P5).
- 카카오톡 공유: **맨 마지막**(P5). 그전까지는 링크 복사 + 기기 공유 시트.

**남은 결정**
1. **공유 주소에 질문 포함** — 기본값을 "미포함"으로 둘지 (제안: 미포함, 체크 시 포함).
2. **커스텀 도메인** — 붙이면 `NEXT_PUBLIC_SITE_URL` 설정 필요. 없으면 `*.vercel.app` 유지.
3. **P2(사주·궁합)와 P3(다시 찾아오기) 순서** — 재방문 효과를 먼저 보려면 P3 먼저도 가능 (서로 의존 없음).
4. **대운 절기 데이터** — 라이브러리 도입 vs 절기 시각 표 커밋 (5.1 선행 과제).
5. **명식 표 방향** — 전통식(오른쪽→왼쪽: 연·월·일·시)과 읽기 쉬운 왼쪽→오른쪽 중 선택.
