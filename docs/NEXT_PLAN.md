## 1. 방향

1. **AI 토큰 0 기조 유지** — 원래 Phase 3(Claude로 운세 문장 생성)는 타로에서 검증한 방식(규칙 기반 이야기 + 외부 AI 이어 보기)으로 대체한다. Claude API 연동은 트래픽·수익 구조가 생긴 뒤 다시 판단한다.
2. **재방문 장치를 로그인 없이 먼저** — TIL 캘린더·스트릭은 로컬 저장으로 시작하고, 로그인·DB는 필요가 확인되면 붙인다.
3. **새 기능 전에 품질 기반** — 배포가 자동으로 되는 만큼 CI·브라우저 확인·SEO 기본기를 먼저 깐다.

## 3. P1 — 타로 경험 다듬기 (약 1–2주)

### 3.1 결과 공유 링크 + 공유 이미지 (가장 효과 큰 과제)
- 지금 결과는 기기에만 저장돼 공유할 수 없다. 결과는 `seed + picks + spread + topic`으로 **서버에서 그대로 재현**되므로 DB 없이 주소만으로 공유할 수 있다.
- `/tarot/r?t=love&s=reunion&seed=…&p=3,17,29,44,61&rev=1` → 서버에서 해석해 결과 화면(카드는 모두 펼친 상태) 렌더.
- 질문은 개인적인 내용일 수 있어 **공유 주소에 넣지 않는다**. 공유할 때 "질문 포함" 체크 시에만 넣는다.
- `opengraph-image.tsx`(ImageResponse)로 뽑은 카드 이미지 + 결론 한 줄을 그린 공유 카드 생성.
- 결과 화면에 "링크 복사" · "카카오톡 공유"(Kakao JS SDK, 키 필요 — 결정 사항) 버튼.
- 완료 기준: 공유 주소를 새 브라우저에서 열면 같은 결과가 나오고, 메신저 미리보기에 카드 이미지가 보인다.

### 3.2 카드 고르기·연출
- 펼친 카드 키보드 조작(←/→ 이동, Enter 선택) — TAROT_PLAN 7장에 계획했지만 아직 버튼 포커스 이동만 됨.
- 고른 카드가 스프레드 자리로 날아가 놓이는 연출, 휴대폰에서는 부채꼴 대신 두 줄 배치 검토.
- `prefers-reduced-motion`은 현재처럼 유지.

### 3.3 작은 개선
- 같은 주제를 짧은 시간에 반복해서 보면 "같은 질문을 반복하면 흐려져요" 안내 (막지는 않음).
- "역방향 포함" 설정을 기억.
- 카드 사전에 **상징 요소**(그림 속 인물·소품·색의 의미) 섹션 — 78장 데이터 작성이 필요해 메이저 22장부터.
- 최근 기록 전체 보기·삭제 (지금은 최근 5개만 표시).

### 3.4 해석 문장 (TAROT_AI_PLAN 후속)
- **T8-3**: 문장 틀 표현 변형 확장 — 자리마다 2개 → 4~5개 (한 번만 초안 생성 후 검수해 커밋, 운영 중 토큰 0).
- **T8-4**: "Claude에서 이어 보기" 버튼 추가(`claude.ai/new?q=` 동작 확인 후), 버튼 클릭 수 집계로 어떤 AI를 많이 쓰는지 확인.

원래 Phase 3 "LLM 풀이"의 토큰 0 버전.

| --- | --- |
| 오늘의 운세 이야기 문단 | 지금은 십신별 고정 문장. 타로 이야기 문단처럼 **십신 × 합충 × 용신 가점/감점 × 분야 점수**를 연결어로 엮어 매일 다르게 읽히는 3~4문장 생성 (`lib/saju/narrative.ts`) |
| 오늘의 운세 AI 이어 보기 | 사주 계산 결과(일간·오늘 일진·십신·합충·분야 점수)를 담은 프롬프트로 ChatGPT·Gemini 이어 보기. 생년월일시는 넣지 않고 **계산된 간지만** 넣어 개인정보 노출 최소화 |

## 5. P2 — 사주 상세 풀이 · 궁합 (약 2–3주)

### 5.1 사주 상세 풀이 `/saju` (PLAN 2.3)
- 온보딩에 저장된 프로필을 그대로 사용 (다시 입력하지 않음).
- 화면: 사주팔자 표(연·월·일·시주, 천간·지지, 지장간) → 오행 분포 차트(목·화·토·금·수) → 신강/신약·용신 → 주제 탭(종합·연애·재물·직업·건강) → 대운 타임라인·올해 운.
- 데이터: `saju-fortune`의 `analyzeSaju` 결과 — 이미 어댑터(`lib/saju/adapter.ts`)가 있음.
- **대화형 Q&A**(원안: Claude + tool use)는 토큰 0 기조에 따라 **"이 사주로 AI에게 물어보기"** 이어 보기로 대체.
- 결과 하단에 적용 범위·한계 안내 (출생시 모름이면 시주 관련 해석은 "잠정").

### 5.2 궁합 `/compat` (PLAN 2.4)
- 나(저장된 프로필) + 상대 입력 → `checkCompatibility` 점수·풀이 → 공유 카드(3.1의 공유 이미지 방식 재사용).
- 상대 정보는 **저장하지 않음**을 기본값으로, 공유 주소에도 넣지 않음.

## 10. 결정이 필요한 것

1. **카카오톡 공유 버튼** — Kakao Developers 앱 등록·JavaScript 키가 필요. 넣을지, 링크 복사만 할지.
2. **공유 주소에 질문 포함** — 기본값을 "미포함"으로 둘지.
3. **커스텀 도메인** — 붙이면 `NEXT_PUBLIC_SITE_URL` 설정 필요. 없으면 `*.vercel.app` 유지.
4. **분석 도구** — 버튼 클릭·스프레드 인기도 집계용으로 Vercel Analytics(간단) / GA4 중 선택. 개인정보 처리 방침 문구 추가 필요.
5. **P2와 P3 순서** — 재방문(캘린더·스트릭)을 사주 상세보다 먼저 할지.
