## 2. B. 외부 AI에서 이어 보기 — ✅ T8-1 구현 완료

### 2.1 동작

결과 화면 맨 아래 **"🤖 AI에게 더 깊게 물어보기"** 섹션 (`src/components/tarot/ask-ai.tsx`)

| 버튼 | 여는 주소 | 입력창 채우기 | 클립보드 |
| --- | --- | --- | --- |
| ChatGPT에서 이어 보기 | `https://chatgpt.com/?q=<프롬프트>` | ✅ 공식 문서는 없지만 널리 쓰이는 `?q=` 파라미터 | 전체 프롬프트 복사 (백업) |
| Gemini에서 이어 보기 | `https://gemini.google.com/app` | ❌ 확장 프로그램 없이는 미지원 | 전체 프롬프트 복사 → "붙여넣기 해 주세요" 안내 |
| 프롬프트만 복사 | — | — | 전체 프롬프트 복사 |

- 링크는 `<a target="_blank">`로 열고, **클릭 순간(새 탭이 포커스를 가져가기 전)에 복사를 시작**해 브라우저의 클립보드 권한 조건을 만족시킨다.
- ChatGPT는 로그인 화면을 거치면 `?q=`가 사라질 수 있어 **항상 클립보드에도 복사**해 둔다.
- 개인정보 고지: "질문과 카드 결과가 선택한 AI 서비스로 전달돼요" 문구를 버튼 아래에 표시.

### 2.2 URL 길이 — 측정값과 대응

한글은 URL 인코딩하면 약 6배로 길어진다. 200가지 무작위 카드 조합으로 잰 인코딩 길이:

| 스프레드 | 전체 프롬프트 | 짧은 판(compact) |
| --- | --- | --- |
| 쓰리 카드 (3장) | 8.3K ~ 10.7K | 더 짧음 |
| 재회·관계 (5장) | 10.3K ~ 12.8K | ✅ 12K 이하 |
| 이번 주 (7장) | 11.8K ~ 14.4K | ✅ 12K 이하 |
| 켈틱 크로스 (10장) | 14.3K ~ 17.5K | ✅ 12K 이하 |

- 상한 `MAX_PREFILL_URL_LENGTH = 12,000` — CDN·프록시의 흔한 URL 제한(8~16KB) 안쪽으로 보수적으로 잡음.
- `aiChatUrl()`: 전체 프롬프트 → 길면 **짧은 판**(카드별 기본 해석·전체 특징 제외) → 그래도 길면 빈 대화 + 클립보드.
- 테스트(`prompt.test.ts`)가 모든 스프레드 × 100가지 조합에서 12K 이하로 미리 채워지는지 확인한다.

### 2.3 프롬프트 구조 (`src/lib/tarot/prompt.ts`)

```
[역할]    20년 경력의 따뜻하고 통찰력 있는 타로 리더, RWS 덱 상징 기반, 한국어
## 상담 정보      주제 · 질문(없으면 "지금 필요한 메시지") · 스프레드(장수) · 역방향 포함 여부
## 뽑은 카드      카드마다: [자리] 카드 이름(영문) — 정/역
                  - 자리의 의미(포지션 질문) - 키워드 / 원소 - 기본 해석(우리 엔진)
## 참고           전체 특징(메이저 비율·수트·원소·숫자·궁정·역방향·조합·흐름)
## 참고           예/아니오 판정 (예/아니오 스프레드일 때)
## 해석 방향      주제별 가이드 1줄 + "기본 해석은 출발점, 그림 속 상징과 자리 의미를 연결"
                  + "카드들을 하나의 이야기로 엮기"
## 답변 형식      1,000~1,500자, 마크다운 소제목
                  1 한 줄 요약 2 카드별 해석(자리→상징→질문에서의 의미) 3 전체 흐름
                  4 질문에 대한 답 5 실천 조언(오늘·이번 주·피할 것) 6 더 물어볼 질문 2개
## 지켜 주세요    공포·단정 금지 / 타인 속마음은 '가능성'으로 / 건강·법률·투자는 전문가 권유 / 따뜻한 존댓말
```

주제별 가이드 (`TOPIC_GUIDE`)

| 주제 | AI에게 주는 방향 |
| --- | --- |
| 오늘·이번 주 | 흐름 + 일·관계·컨디션에서 신경 쓸 점 |
| 연애 | 관계의 흐름과 감정 교류, 관계를 건강하게 가꾸는 법 |
| 속마음 | 상대 마음은 '가능성'으로, 직접 확인할 대화 방법 제안 |
| 재회 | 원인과 가능성 + 재회만이 답은 아니라는 관점, **연락 강요·집착 조언 금지** |
| 직업·이직 | 준비 순서·점검 항목 중심, 이직·퇴사 단정 금지 |
| 금전 | 지출·저축 습관 중심, **투자 상품·종목·시점 추천 금지** |
| 학업·시험 | 공부 방향·집중력·컨디션 |
| 인간관계 | 소통 방식과 경계, 구체적인 말과 행동 |
| 예/아니오 | "예 / 아니오 / 조건부"로 먼저 답하고 근거 카드·바꿀 수 있는 조건 |
| 자유 질문 | 질문 의도를 먼저 짚고 해석 |

### 2.4 한계와 대응

| 한계 | 대응 |
| --- | --- |
| `?q=`는 OpenAI 공식 기능이 아님 — 언제든 바뀔 수 있음 | 클립보드 백업을 항상 유지. 동작이 바뀌면 `aiChatUrl`만 수정 |

## 3. A. 규칙 기반 "이야기" 문단 — ▶ T8-2 다음 작업

지금 결과 화면은 카드별 해석이 목록으로 나열된다. 이를 **리더가 말하듯 이어지는 한 문단**으로 엮는 단계를 추가한다. 같은 요청이면 항상 같은 문장이 나온다.

### 3.1 출력 예 (재회 스프레드)

> 두 사람이 멀어진 데는 **소드 3**이 보여 주듯 말로 받은 상처가 컸어요. 그 사람은 지금 **컵 6**처럼 함께한 추억을 떠올리고 있고, 당신도 **완드 6**의 모습으로 한층 단단해졌어요. 다만 **소드 8**이 재회 자리에 나와, 서로 스스로 만든 벽이 남아 있어요. 그래서 **소드 9**의 조언처럼 걱정을 적어 보고 실제로 일어난 일만 남겨 보세요.

### 3.2 설계

```
src/lib/tarot/narrative/
  index.ts          buildNarrative(reading) → string (2~5문장)
  templates.ts      스프레드 유형별 문장 틀
  connectors.ts     흐름에 따른 연결어 선택
  phrases.ts        카드별 짧은 구절(명사구) — 문장 속에 끼워 넣을 용도
```

1. **스프레드 유형별 문장 틀**

   | 유형 | 해당 스프레드 | 문장 뼈대 |
   | --- | --- | --- |
   | 시간 흐름 | 과거·현재·미래, 켈틱 크로스 일부 | 과거엔 {A} → 지금은 {B} → 앞으로 {C} |
   | 행동 | 상황·행동·결과, 예/아니오 | 지금 {A}, 그래서 {B}를 하면 {C} |
   | 관계 | 관계, 재회 | 나는 {A}, 상대는 {B}, 둘 사이엔 {C}, 그러나 {D}, 앞으로 {E} |
   | 선택 | 양자택일 | 지금 {A}. A를 고르면 {B}→{C}, B를 고르면 {D}→{E} → 점수 비교로 권유 |
   | 주간 | 이번 주 | 좋은 날 {X요일}, 조심할 날 {Y요일}, 주간 키워드 |
   | 단일 | 원 카드 | 기존 요약 그대로 |

2. **연결어 선택** — 앞 카드와 뒤 카드의 점수(예/아니오 점수 − 역방향 감점) 차이로 고른다.
   - 좋아짐(≥ +1): "하지만 이제", "그 덕분에" / 나빠짐(≤ −1): "다만", "그런데" / 비슷함: "그리고", "이어서"
   - 같은 연결어가 한 문단에 두 번 나오지 않게 한다.

3. **카드별 짧은 구절 (`phrases.ts`)** — 긴 해석 문장은 문단 속에 넣기 어렵다. 카드 × 정/역마다 **10~20자 명사구**를 새로 작성한다.
   - 예: 소드 3 정 → "말로 받은 상처", 컵 6 정 → "함께한 추억", 소드 8 정 → "스스로 만든 벽"
   - 분량: 78장 × 2 = 156개. 없으면 첫 키워드로 대체한다.

4. **변형** — 같은 틀이 반복되면 기계적으로 읽힌다. 틀마다 표현을 2~3개 준비하고, `seed`로 골라 재현성을 유지한다.

5. **조사** — 기존 `josa()` 재사용 (카드 이름·구절 끝 받침).

### 3.3 화면

- 종합 해석 카드 맨 위에 "📜 카드가 들려주는 이야기" 문단 추가. 그 아래에 기존 요약·특징·조언.
- 외부 AI 프롬프트의 '기본 해석' 옆에도 이 문단을 넣어 AI가 흐름을 이어받게 한다 (짧은 판에서는 제외).

### 3.4 테스트

- 모든 스프레드 × 무작위 200가지 조합: 빈 문장·`undefined`·`(이)가` 같은 조사 미처리 없음
- 한 문단 안에서 연결어 중복 없음, 길이 80~400자
- 같은 요청 → 같은 문단 (재현성)
- 대표 조합 몇 개는 기대 문장을 그대로 비교하는 스냅샷 테스트

### 3.5 작업량 (예상)

| 작업 | 분량 |
| --- | --- |
| 문장 틀·연결어·조립 로직 | 1일 |
| 카드별 짧은 구절 156개 작성 | 1일 |
| 화면·프롬프트 연동, 테스트 | 0.5일 |

## 4. F. 문장 틀 변형을 한 번만 만들어 두기 — T8-3 (선택)

A의 표현 변형(3.2-4)을 사람이 다 쓰기 어렵다면, **개발할 때 한 번만** AI로 초안을 만들고 사람이 검수해 데이터 파일로 커밋한다.

- 사용자 요청마다 호출하지 않으므로 **운영 중 AI 비용은 0**. 초안 작성은 무료 ChatGPT·Gemini 웹에서 해도 된다.
- 절차: 문장 틀과 조건을 프롬프트로 정리 → 틀마다 변형 5개 생성 → 검수(톤·단정 표현·조사) → `templates.ts`에 반영 → 테스트
- 검수 기준은 2.3의 "지켜 주세요" 규칙과 같다.

## 5. 보류한 방법 — 다시 볼 조건

### C. 자체 서버에서 오픈소스 LLM
- 구성: 추론 서버(Ollama·vLLM 등) + 한국어가 되는 7B~14B급 오픈 모델(Qwen·Gemma 계열 등). `seed + picks + topic`을 키로 결과를 캐시.
- 문제: GPU 서버 상시 비용, 운영 부담, 작은 모델의 한국어 문장 품질 편차, **모델별 라이선스(상업적 사용 가능 여부) 개별 확인 필요**.
- **재검토 조건:** 월간 결과 조회가 충분히 많아 외부 AI로 넘기는 이탈이 문제 되거나, A의 품질로 부족하다는 피드백이 쌓일 때.

### D. 사용자 브라우저에서 모델 실행 (WebLLM·transformers.js·브라우저 내장 AI)
- 장점: 서버 비용 0, 데이터가 기기 밖으로 나가지 않음.
- 문제: 수백 MB~수 GB 모델 다운로드, WebGPU·지원 브라우저 제한, 휴대폰 성능, 작은 모델의 한국어 품질.
- **재검토 조건:** 브라우저 내장 AI가 주요 브라우저에서 한국어를 안정적으로 지원할 때.

### E. 다른 회사의 무료 API
- 문제: 무료 등급은 사용량 제한이 빡빡하고, 입력이 모델 개선에 쓰일 수 있어 **사용자의 고민 질문을 보내기 부적절**. 유료로 바꾸면 결국 토큰 비용.
- **재검토 조건:** 없음 (유료 LLM을 쓴다면 원래 계획인 Claude 연동과 비교).
